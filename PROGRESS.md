## Decisions
- **Next.js 16.4.2** (latest stable, Turbopack, React 19.3). The bundled docs in
  `node_modules/next/dist/docs/` were checked for breaking changes.
- **Cache Components turned off** (`cacheComponents: false`): all resume data lives in the
  browser and the only server code is uncached POST AI routes.
- `npm run typecheck` = `next typegen && tsc --noEmit` (route types such as `LayoutProps` are
  generated by Next).
- **Models** (checked against official docs 2026-10-22): Gemini `gemini-3.6-flash` (free tier,
  `thinkingLevel: MINIMAL`); Groq fallback `openai/gpt-oss-120b`. Groq's Llama models are now
  listed as contact-sales, and gpt-oss is on the free-tier limits table. All in `src/config/ai.ts`.
- `@types/node` pinned to v22 (Vitest 5 peer requirement).
- `.gitignore` ignores `.env*` but allows `.env.example`. `.env.local` was created with
  placeholders only.
- Dark mode is class-based (`.dark` on `<html>`), stored in localStorage, applied before
  paint by an inline script. The resume preview uses `.resume-paper` (always white).
- Settings (theme, BYOK Gemini key, AI-notice flag) are in `src/lib/settings.ts` (localStorage).
- A git repo was initialised locally so ignore rules can be verified. Nothing is committed.

### Phase 2
- `src/lib/resume/schema.ts`: Zod model, `SCHEMA_VERSION = 2`, `migrateResume()` (v1 → v2:
  flat skills array, newline bullets, top-level template, string references), factory defaults
  (no shared arrays), `emptyItem` factories, `normalizeLayout`.
- `src/lib/resume/sections.ts`: default + ATS-standard headings, visibility helpers.
- `src/lib/resume/history.ts`: pure undo/redo with coalescing (same field within 1s = one
  step), capped at 100.
- `src/lib/resume/storage.ts`: repository over a KeyValueStore (IndexedDB via idb-keyval →
  localStorage → memory fallback); one key per resume plus an index; `StorageFullError`.
- `src/hooks/useResumeStore.tsx`: React provider (in root layout) with an `update(recipe,
  coalesceKey)` API, auto-save 400ms after each change, undo/redo + Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y.
- `src/lib/export/json.ts`: backup format, per-resume migration/validation, id clash → new id.
- `src/data/sample-resume.ts`: fake "Priya Sharma".
- Bullets are `string[]` (reordered with up/down); list items have ids (drag-and-drop).

### Phase 3
- `src/lib/resume/render-model.ts` — THE shared model (`buildRenderDoc`): header, contacts with
  hrefs, sections → entries {title, subtitle, date, meta, text, bullets}. Date formatting,
  `suggestFileName` (Firstname_Lastname_Resume.pdf). Creative puts skills, certifications,
  hobbies and references in a sidebar column. Photos only render in creative.
- `src/lib/resume/template-style.ts` — per-template tokens shared by preview and PDF.
- `src/components/resume/ResumePreview.tsx` — pure HTML page in mm/pt units (hook-free, so it
  renders on the server for landing thumbnails). Highlights `[placeholders]`.
- `src/lib/resume/page-fit.ts` + `LivePreview.tsx` — measures natural height, shows page-break
  lines, "fits on 1 page" badge vs the country's student page target. "Fit to one page"
  tightens gap → line height → margins → font size, one step per frame, within
  `LAYOUT_LIMITS`.
- `DesignPanel.tsx` — template picker (non-ATS warning), accent palette, 5 fonts, date
  format, A4/Letter, sliders.

  one page, 360px with no horizontal scroll.

### Phase 5
- `src/lib/checks/honesty.ts` — `findNewDetails(original | original[], output)` flags numbers
  (incl. number words: "three" = 3), percentages, currency (₹/Rs/$/€/£/INR, lakh/crore), dates
  (month + year, years) and proper nouns / ALL-CAPS tools. Known if present anywhere in the
  sources (case/format-insensitive). Ignores `[placeholders]`. Skips verb-looking sentence
  starts and a common-word/action-verb list. `highlightSegments` is for UI highlighting.
- `placeholders.ts` — `collectPlaceholders(resume)` with locations (export checklist, Phase 9).
- `ats.ts` — 100-point score: headings 15, contact 15, ATS template 15, font 10, length 10
  (word count + measured pages), dates 10, empty entries 10, links 10, core sections 5, file
  name tip. Empty/vacuous checks do not earn points.
- `quality.ts` — weak openers (fix: remove phrase), pronouns (fix: remove), long bullets
  (>200 chars), repeated verbs (3+ overall or 2× in one item; fix: alternative verb),
  missing dates.
- `country.ts` — config tips + resume-specific warnings (photo, pages, paper, India
  board/percentage).
- UI: `ChecksPanel` (editor "Checks" tab) with an animated `ScoreRing` (respects reduced motion),
  quick-fix buttons (applied only if the bullet is unchanged), a placeholder list and country tips.
  `renderIssueTools` is a slot for AI "Shorter" on long bullets (Phase 7).

### Phase 6
- `src/lib/ai/contracts.ts` — input + output Zod schemas for all 9 actions (bullets, polish,
  summary, skills, tailor, activity, grammar, import, trim). Shared by client and server.
  Lines are addressed by `ref` strings (e.g. "experience.2.1") so replies map back to bullets.
- `prompts.ts` — compact system prompts, each starting with `HONESTY_RULES` + `INJECTION_GUARD`;
  user text wrapped in `<data>` tags (forged `</data>` stripped). Per-action code `validate`
  (cited ids/refs must exist, char limits → corrective retry) and `finalize` (activity limits
  truncated by grapheme, duplicate/existing skills dropped, no-op grammar fixes dropped).
- `handler.ts` — rate limit → body size + Zod → `stripContact` → mock or `runAi` → finalize.
  BYOK header `x-gemini-key` overrides the server Gemini key; `PASTE_…` placeholders count as
  no key. Route: `src/app/api/ai/[action]/route.ts` (`maxDuration = 60`).
- `rate-limit.ts` — in-memory sliding window per IP (40/hour), best-effort on serverless.
- `mock.ts` — `MOCK_AI=true` (never in production). The polish mock invents "by 40%" on
  purpose so the honesty check can be shown flagging it.
- `client.ts` — `callAi(action, input)` for the browser; never throws, returns friendly errors.
- `src/lib/text/char-count.ts` — grapheme counting (`Intl.Segmenter`) for activity limits.
- Phase 7 should: build inputs without contact fields, run `findNewDetails` on every AI
  output, show Accept / Edit / Reject, countdown on `rate-limit` using `retryAfterSeconds`,
  and show the AI privacy notice once (`aiNoticeAccepted`).

- Honesty sources: polish/shorter → the item's own fields; summary/tailor/grammar → the

- Wiring: per-bullet Polish + Shorter (`BulletToolsContext`), Summary writer, Skills

  Grammar check + "Shorter" on long-bullet issues in Checks, "Turn into bullets" in the

### Phase 8
- `/import` (`ImportFlow`): 1) upload PDF/.docx (drag-drop or picker, 5 MB) or paste →
  2) check/fix the extracted text → "Read with AI" or "Read without AI (basic)" →
  3) review: version name, include/exclude sections (with counts), live preview, contact
  found → "Use this resume" opens it in the editor. Nothing is saved before step 3.
- `src/lib/import/extract.ts` — browser-only extraction (pdfjs-dist, mammoth); friendly
  errors for scanned/encrypted/unsupported files. The pdf.js worker is copied to
  `public/pdf.worker.min.mjs` by `scripts/copy-pdf-worker.mjs` (predev/prebuild; git-ignored)
  — `new URL(..., import.meta.url)` caused a Turbopack server-bundle warning.
- `src/lib/import/map.ts` — `importedToResume` (date normalisation, "Present" → current,
  final `resumeSchema.parse`), `detectContact` (email/phone/links found locally, never from
  the AI), `parseByHeadings` (no-AI fallback; wording copied exactly).
- Fixtures (fake "Arjun Testwala"): `tests/fixtures/import-sample.mjs` +
  `sample-import.pdf/.docx` generated by `node scripts/make-fixtures.mjs`.
- `scripts/check-import.mjs` — browser check (PDF basic, .docx AI mock, save, bad file).

### Phase 9

- DOCX (`docx.ts`): Title + Heading1 styles, real bullet numbering, right tab stop for dates,
